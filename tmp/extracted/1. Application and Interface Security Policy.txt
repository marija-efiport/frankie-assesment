API  standards  
1.  All  APIs  that  will  be  used  within  the  platform  should  be  protected  with  IP  
address
 
whitelisting
 
and
 
authentication.
 
The
 
ones
 
that
 
will
 
be
 
used
 
as
 
endpoints
 
for
 
any
 
purpose
 
outside
 
the
 
platform,
 
should
 
have
 
at
 
least
 
basic
 
authentication
 
and
 
adequate
 
protection
 
depending
 
on
 
the
 
data
 
sensitivity
 
and
 
potential
 
requirements
 
made
 
by
 
the
 
client.
 2.  When  creating  or  editing  an  existing  API,  any  changes  made  are  reviewed  by  a  
person
 
with
 
OWASP
 
standards
 
knowledge,
 
usually
 
that
 
being
 
a
 
tech
 
lead
 
on
 
the
 
project.
 
The
 
API
 
should
 
then
 
be
 
tested
 
with
 
unit
 
tests
 
and
 
in
 
a
 
sandbox
 
environment.
 3.  For  more  sensitive  information,  additional  steps  are  required,  depending  on  the  
level
 
of
 
information
 
sensitivity.

1.  Data  validation  code  is  required  to  validate  all  data  created  outside  the  platform  
before
 
it
 
can
 
enter
 
the
 
platform.
 2.  Data  validation  code  should  be  reviewed  by  a  person  with  OWASP  standards  
knowledge,
 
usually
 
that
 
being
 
a
 
tech
 
lead
 
on
 
the
 
project,
 
and
 
tested
 
with
 
unit
 
tests
 
and
 
in
 
a
 
sandbox
 
environment.
 
Additionally,

code

to
 
periodical

in

to

or
 
errors
 
which
 
might

emerged
 
as

of
 
changes
 
made
 
outside
 
the
 
platform
 
between
 
the
 
tests.
 3.  Same  goes  for  the  output  data,  the  entire  code  which  communicates  with  
anything
 
outside
 
the
 
platform
 
should
 
also
 
be
 
reviewed
 
by
 
a
 
person
 
with
 
OWASP
 
standards
 
knowledge,
 
usually
 
that
 
being
 
a
 
tech
 
lead
 
on
 
the
 
project,
 
and
 
tested
 
with
 
unit
 
tests
 
and
 
in
 
a
 
sandbox
 
environment.
 4.  If  the  error  is  detected  in  the  data  validation  process,  a  list  of  steps  should  be  
taken
 
in

to
 
ﬁx

First,

should

existing

in

Data  access  
1.  Access  to  data  stored  on  a  project  should  be  regulated  based  on  data  sensitivity  
and
 
whether
 
the
 
data
 
is
 
required
 
for
 
working
 
on
 
the
 
project.
 
When

the
 
platform

any

can
 
be

irreversible
 
hash
 
functions.
 2.  Each  project  should  go  through  periodic  data  sensitivity  evaluations  which  might  
further
 
increase
 
measures
 
taken
 
to
 
ensure
 
data
 
security.

any

in
 
which
